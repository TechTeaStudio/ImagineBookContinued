# v1.3.0.1 Modrinth releases from CI

## Summary

1.3.0.1 changes only how the mod is released. The mod code is identical to 1.3.0.0, so updating changes nothing in game. It is the first version meant to reach Modrinth through CI: a `v<VERSION>` tag on `product` builds, tests and publishes both jars. `CHANGELOG.md` in the repository is the line-by-line source; this note adds context.

Never released: the first CI run on `product` failed at `runMixinSmoke` (duplicate `fabric.mod.json` in the smoke source set), so 1.3.0.1 was never tagged or published; fixed in [[v1.3.0.2 First Modrinth release]].

## Shipped in 1.3.0.1

From `CHANGELOG.md`:

- The mod itself is unchanged from 1.3.0.0.
- Releases are now published to Modrinth automatically from a version tag, each with its sources jar.

## What changed in the repository

| Change | Detail | Where |
|---|---|---|
| Tag-only publish | The workflow triggers on `v*` tags as well as `product`; the Modrinth and GitHub Release steps run only on a tag. A push that changes only CI or docs does not publish. | `.github/workflows/build.yml`; [[Publish to Modrinth from version tags with an in-repo script]] |
| Publish script | Standard-library Python. Checks the tag against `VERSION`, takes the `CHANGELOG.md` section as the changelog, needs both jars, skips a version already on Modrinth. Sends `<VERSION>+26.3`, named `<VERSION> for Minecraft 26.3`, Fabric, client only, the sources jar marked `sources-jar`, Fabric API required and Stendhal optional by project ID. `--dry-run` prints the data without sending. | `tools/publish_modrinth.py`; [[Release to Modrinth]] |
| Script tests | Unit tests for the changelog section, tag check, version data, jar lookup, multipart body and token handling. CI runs them with `python3 -m unittest discover -s tools -p "test_*.py"` after the Gradle build. | `tools/test_publish_modrinth.py` |
| Token | Repository secret `MODRINTH_TOKEN`, a Modrinth personal access token with Create versions, Read projects and Read versions; the project is `MODRINTH_PROJECT: imaginebook-continued`. | `.github/workflows/build.yml` |
| Release flow | A release is `git tag v<VERSION> product`, then pushing the tag. | `CLAUDE.md` (Release flow) |
