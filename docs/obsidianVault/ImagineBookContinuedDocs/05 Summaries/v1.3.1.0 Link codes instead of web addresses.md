# v1.3.1.0 Link codes instead of web addresses

## Summary

1.3.1.0 keeps web addresses out of book text. The visible tag stays, but its link part is now a code: `imgur:<id>` for an Imgur picture, `u:<base64url>` for any other link. The game still downloads from the real address. It answers the owner's question of 2026-11-17 about servers that block web links in books. `CHANGELOG.md` in the repository is the line-by-line source; this note adds context.

## Shipped in 1.3.1.0

From `CHANGELOG.md`:

> - Books no longer contain web addresses, so servers that filter links accept them. A pasted Imgur link is stored as `imgur:<id>`, any other link as `u:` and its address in base64url; the game still downloads from the real address. The link field keeps showing the real link.
> - Books with plain `https://` links keep working.
> - ImagineBook versions before 1.3.1.0 (the original mod and other 26.x ports included) cannot read the new codes and show the error picture for them.
> - Fixed: a link over 255 characters showed the raw key `imaginebook.error.too_long` instead of the message.

## Why

The owner asked whether the book could store the picture itself, because some servers block web links in book text. It cannot in practice: a book and quill holds about 75 KB as base64, while an Imgur picture is usually 100 to 500 KB. The answer, the options and the backward-compatibility cost are in [[Store link codes, not pictures, in book text]].

## What changed

- `util/LinkCodes` (new): `encode` turns a link into its code, `decode` gives the real address back. Codes have no scheme, no dot and no comma; `imgur:<id>` opens as `https://i.imgur.com/<id>.png`, and downloads are re-encoded to PNG by content, so the extension does not matter.
- `resolvers/CodedLinkResolver` (new): resolves `imgur:` and `u:` by decoding and downloading the real address; only an `http(s)` result is downloaded, anything else gives the error picture.
- `Imaginebook`: the resolver map gains `imgur` and `u` beside `http`, `https` and `res`.
- `mixin/NewBookEditScreenMixin`: the URL field responder stores `LinkCodes.encode(Imaginebook.fixImgurLink(url))` and compares the field with the decoded stored link; `updateFields()` shows the decoded link. The player sees the real link, the book holds the code.
- Translation fix: the responder asked for `imaginebook.error.too_long`, a key in none of the language files, so the field showed the raw key. It now uses `imaginebook.error.url_too_long`, present in `en_us`, `ru_ru` and `uk_ua`.

## Book formats at a glance

| Format | Written by | Link visible | Read by 1.3.1.0 |
|---|---|---|---|
| Hidden binary: page padded to 1023 characters, base64 metadata on the last line | the original mod until commit `28ba12b` (2025-01-17) | no | yes, in the reader only |
| Visible tag with a plain `http(s)` link | from 28ba12b up to 1.3.0.3 | yes | yes |
| Visible tag with a link code | 1.3.1.0 and later | no | yes |

A book written with 1.3.1.0 shows its pictures only to players on 1.3.1.0 or later; older versions show the error picture for each code.

## Verification

- 48 JUnit tests (39 before, plus 9 in the new `LinkCodesTest`) and 13 Python tests pass.
- `tools/mixin_smoke.py` passed with Stendhal 1.4.9.
- Not yet checked in game. Stendhal is disabled in the owner's instance at present, so the in-game check runs on the vanilla editor.
- No server with a link filter has been tried yet.
