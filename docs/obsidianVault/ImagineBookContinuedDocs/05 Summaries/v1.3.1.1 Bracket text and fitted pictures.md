# v1.3.1.1 Bracket text and fitted pictures

## Summary

1.3.1.1 fixes faults found in 1.3.1.0 before that version was released, so it supersedes 1.3.1.0 and is the first version meant to ship the link codes. Bracketed text such as `[1]` no longer breaks a picture, a new picture starts on the page's text area and shrinks to fit it, and the size-limit log message gives the real limit. `CHANGELOG.md` in the repository is the line-by-line source; this note adds context.

## Shipped in 1.3.1.1

From `CHANGELOG.md`:

> - Fixed: text in square brackets on a page, such as `[1]`, broke pictures. A picture after it on the same line did not show, and moving or editing a picture could rewrite that text instead of the picture's tag. Only real image tags count now, and a tag never runs across lines.
> - A new picture starts on the page's text area and, once it has loaded, shrinks to fit it. 100 % is the picture's own pixel size, so a photo used to cover the whole book. Pictures already in books keep their size.
> - Fixed: the log called the download size limit 1 MB; it is 8 MB.

## How it was found

On 2026-11-17 the owner reported "Found a problem" with 1.3.1.0, without details. 1.3.1.0 had been committed as `a5bc93c` and never pushed or released. Reviewing the code then found the four faults below; which of them the owner ran into is not known.

## Faults and fixes

### Edits rewrote bracketed text instead of the tag

- `mixin/NewBookEditScreenMixin.mutateImage` found the tag to rewrite by counting every `\[.*?\]` on the page, while the list of pictures counts image tags only (`ImageTags.PATTERN` through `ImageSerializer.parseSafeModeImages`). With `[1]` before a picture, moving or editing that picture rewrote `[1]`.
- Fix: `util/ImageTags.replace(page, index, replacement)` replaces the index-th image tag, counted exactly as the picture list counts them. An index outside the tags leaves the page unchanged; an empty replacement removes the tag. `mutateImage` now calls it.

### The tag pattern let the link run over brackets and lines

Found while writing the test for the fix above. The pattern, unchanged since the original mod, excluded only commas from the link part:

| Versions | `ImageTags.PATTERN` | Link part |
|---|---|---|
| original mod to 1.3.1.0 | `\[[^,]*?(,[+-]?\d+(\.\d+)?){2,5}\]` | anything but a comma, newlines included |
| 1.3.1.1 | `\[[^,\[\]\s]*?(,[+-]?\d+(\.\d+)?){2,5}\]` | no comma, bracket or whitespace |

- With the old pattern, `[1] and [note]: [https://...,1,2]` matched as one tag whose link started at `1]`, so a picture after bracketed text on the same line never showed. Because the link part also allowed newlines, a tag could run across lines.
- The reader hides and the editor fades exactly the spans the pattern finds (`BookScreenMixin`, `MultiLineEditBoxMixin`), so the same bad span also decided what was hidden and faded ([[Fade tags in the editor, hide them in the reader]]).
- Compatibility: tags written by any version with a real link still parse. Link codes use only letters, digits, `-`, `_` and the prefix colon ([[Store link codes, not pictures, in book text]]).

### New pictures covered the book

100 % is the picture's own pixel size, so a 1000 x 1000 photo covered the whole book until it was shrunk by hand. Add image also put it at x 0, y 0, the book's top left edge. The fix lives in `util/ImageFit` and `NewBookEditScreenMixin`:

- Add image creates the picture at x 36, y 30 (`ImageFit.PAGE_X`, `PAGE_Y`: `BookViewScreen.PAGE_TEXT_X_OFFSET` and `PAGE_TEXT_Y_OFFSET` in 26.3), the corner of the page's text area.
- Entering a link in the URL field resets the size to 100 %, as before, and now marks the picture for fitting. `imaginebook$fitLoaded()`, called from the editor's render hook every frame, waits until the real picture has loaded; a placeholder (downloading, failed, too big, bad link) does not count.
- It then sets width and height to `ImageFit.percent(w, h)`: the largest whole percent, at most 100 and at least 1, at which the picture fits 114 x 126 (`BookEditScreen.TEXT_WIDTH` and `TEXT_HEIGHT` in 26.3). Both get the same percent, so the aspect ratio is kept. A 1000 x 1000 picture becomes 11 %; a picture smaller than the area stays at 100 %.
- A pending fit is dropped when the page changes or the picture is gone before it loads.
- Pictures already in books keep their size: opening a book refits nothing.

### Size-limit message

`resolvers/AsyncImageDownloader` refuses a download over 8 MB but logged "File size exceeds 1MB limit." The message is now built from the limit and says 8 MB.

## Verification

- 60 JUnit tests (48 at 1.3.1.0, plus 6 in `ImageTagsTest` and 6 in the new `ImageFitTest`) and 13 Python tests pass.
- `ImageTagsTest` pins bracketed text before a tag, `replace` and tags that never cross a line or a space; `ImageFitTest` pins `percent` (including a sweep up to 3000 x 3000), the 26.3 constants, and that the editor and downloader sources use the fixes.
- `tools/mixin_smoke.py` passed with Stendhal 1.4.9, loaded from a temporary copy: the owner keeps Stendhal disabled now.
- Not yet checked in game.
