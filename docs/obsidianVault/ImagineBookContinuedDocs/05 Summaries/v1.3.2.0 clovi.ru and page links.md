# v1.3.2.0 clovi.ru and page links

## Summary

1.3.2.0 adds clovi.ru: a file link and a post link each get a short code, so the book still holds no web address. It also adds a general rule to the downloader: when a link leads to a web page instead of a picture, the game follows the page's preview picture once. That is what makes clovi posts show, and other sites with a preview picture as well. It also stops the editor from rewriting Imgur album and gallery links into addresses that do not exist; they now stay page links and use the same step. 1.3.1.0 and 1.3.1.1 were never released, so 1.3.2.0 is the first version meant to ship the link codes and the 1.3.1.1 fixes. `CHANGELOG.md` in the repository is the line-by-line source; this note adds context.

## Shipped in 1.3.2.0

From `CHANGELOG.md`:

> - clovi.ru support. A file link (`clovi.ru/f/<id>`) is stored as `clovi:<id>`, a post link (`clovi.ru/post/<number>`) as `clovi:post/<number>`.
> - Links to a web page instead of a picture now work when the page names a preview picture (`og:image`, else `twitter:image`): the game follows that address once, under the same 8 MB limit and timeouts, and caches the picture under the page's address. This is how clovi posts show.
> - Fixed: an Imgur album or gallery link (`imgur.com/a/...`, `imgur.com/gallery/...`) was rewritten into `i.imgur.com/<rest>.png`, an address that does not exist. Only a single-picture page (`imgur.com/<id>`) becomes a direct link now; albums and galleries stay page links and use the page's preview picture.

## Request

On 2026-11-17 the owner asked for clovi.ru support, with https://clovi.ru/post/12207 as the example. What that address serves:

- The post is an HTML page of 7.5 KB, not a picture. Its `og:image` (and `og:image:secure_url`) is the relative address `/f/YwUDL2J`.
- https://clovi.ru/f/YwUDL2J serves the picture itself: a JPEG, 564 x 553, 29.5 KB. The page's `og:image:type` says `image/png`; that does not matter, because downloads are decoded by content.

## What changed

### clovi codes

- `util/LinkCodes.encode` turns `http(s)://[www.]clovi.ru/f/<id>` (4 to 16 letters and digits, an optional trailing slash) into `clovi:<id>`, and `http(s)://[www.]clovi.ru/post/<number>` (1 to 12 digits) into `clovi:post/<number>`. Imgur links are matched first; any other web link still becomes `u:<base64url>`.
- `LinkCodes.decode` opens `clovi:<id>` as `https://clovi.ru/f/<id>` and `clovi:post/<number>` as `https://clovi.ru/post/<number>`. Anything else after `clovi:` comes back unchanged and gives the error picture.
- `resolvers/CodedLinkResolver.CLOVI` is registered under `clovi` in the resolver map of `Imaginebook`, beside `imgur` and `u`.

A file code resolves straight to the picture. A post code resolves to a page, and the page step below turns it into the picture. The codes are wire format: see [[Store link codes, not pictures, in book text]].

### Page previews

- `resolvers/PagePreview` (new). `looksLikeImage(bytes)` recognises PNG, JPEG, GIF, WebP and BMP by their first bytes. `find(html, page)` reads the `<meta>` tags and returns the first web address among `og:image`, `og:image:secure_url`, `og:image:url` and `twitter:image`, in that order: attributes in either order and either quote, common entities decoded, a relative address resolved against the page, only `http` and `https` accepted.
- `resolvers/AsyncImageDownloader.downloadThread`: a download that is not a picture is searched for a preview; if one is found, that address is opened once with the same timeouts and User-Agent and read under the same limit. The picture is converted to PNG and cached under the page's address. A page without a preview, or a preview that is itself not a picture, gives the error picture with the usual retries.
- `readLimited(in, downloadURI)` (new) holds the 8 MB read loop for both requests; a preview over the limit counts against the page's address and shows the size error. It throws `IOException` instead of the ICU `InvalidFormatException` the old loop borrowed.

Why the rule lives in the downloader and not in the editor: [[Follow a page's preview picture once]].

### Imgur albums and galleries

Found during the 1.3.2.0 review: the editor's URL field ran every link through `Imaginebook.fixImgurLink` before `LinkCodes.encode`, and `fixImgurLink` turned every `https://imgur.com/<rest>` into `https://i.imgur.com/<rest>.png`. An album (`imgur.com/a/...`) or gallery (`imgur.com/gallery/...`) link became `i.imgur.com/<rest>.png`, an address that does not exist, and was stored as its `u:` code.

- `util/LinkCodes.directImgurLink` (new) turns only a single-picture page, `http(s)://imgur.com/<id>` (5 to 10 letters and digits, an optional trailing slash), into `https://i.imgur.com/<id>.png`; any other link comes back unchanged.
- `Imaginebook.fixImgurLink` now just calls `LinkCodes.directImgurLink`.
- A single-picture page still ends as `imgur:<id>`. Album and gallery links stay page links, are stored as `u:` codes of the real page, and go through the page-preview step.

## Verification

- 71 JUnit tests (60 at 1.3.1.1, plus 4 in `LinkCodesTest`: 2 for clovi, 2 for Imgur albums and galleries; and 7 in the new `PagePreviewTest`) and 13 Python tests pass.
- `LinkCodesTest.imgurAlbumsAndGalleriesStayPages` pins that a single-picture page becomes the direct link while `imgur.com/a/...` and `imgur.com/gallery/...` survive encoding as page links; `editorFixesImgurLinksThroughLinkCodes` checks that `fixImgurLink` delegates to `directImgurLink`.
- `PagePreviewTest` parses the head of the real clovi post page as served on 2026-11-17.
- `tools/mixin_smoke.py` passed with Stendhal 1.4.9, loaded from a temporary copy.
- Live check with the mod's own classes: `clovi:post/12207` decodes to the post page, the page is not a picture, its preview is https://clovi.ru/f/YwUDL2J, and that address returns JPEG bytes.
- Live check of an Imgur page on 2026-11-17: https://imgur.com/MK3eW3A is HTML whose `twitter:image` is https://i.imgur.com/MK3eW3Ah.jpg, and `PagePreview` finds it. No album or gallery page was fetched.
- Not yet checked in game.
