# v1.3.2.1 Release notes since the last upload

## Summary

1.3.2.1 ships the mod code of 1.3.2.0 unchanged and fixes how its release notes are made. Three versions were committed after the last Modrinth upload and never uploaded themselves; the release script would have sent only the newest `CHANGELOG.md` section, so their changes would never have reached players' notes. The script now collects every section since the last upload. `CHANGELOG.md` in the repository is the line-by-line source; this note adds context.

## Shipped in 1.3.2.1

From `CHANGELOG.md`:

> - The mod itself is unchanged from 1.3.2.0.
> - Release notes on Modrinth now list every version since the previous upload, so the changes of 1.3.1.0 and 1.3.1.1, which were never uploaded on their own, reach players too.
> - Shorter, simpler Modrinth page text.

`tools/publish_modrinth.py` sent the `## <VERSION>` section only. Tagging 1.3.2.0 would have put the clovi and page-preview notes on Modrinth, but not the link codes (1.3.1.0), the bracket fix or the picture fitting (1.3.1.1).

## What changed

### Release notes since the last upload

- `changelog_since(text, version, published)` (new) walks the `## ` headings of `CHANGELOG.md` from `VERSION` downwards and collects versions until it reaches one already on Modrinth, or a heading that is not a four-part fork version (`FORK_VERSION`, so `## 1.2.9 (upstream and the 26.x port)` stops it). Several sections are joined, each under a `### <version>` heading.
- A first upload (nothing on Modrinth) and the next version right after an upload keep their single plain section, as before.
- `published_versions(versions)` (new) turns the project's version list into plain numbers, cutting the `+26.3` suffix.
- `main` passes the versions already on Modrinth, the same list it uses to skip a version that is already up.

For 1.3.2.1, with 1.3.0.2 and 1.3.0.3 on Modrinth, the notes are the sections of 1.3.2.1, 1.3.2.0, 1.3.1.1 and 1.3.1.0. Details and the general rule: [[Release to Modrinth#Release notes since the last upload]].

### Preview with --since

A dry run talks to nobody, so it cannot know what is on Modrinth. `--dry-run --since <versions>` treats the listed versions as uploaded and prints the notes the tag run would send:

```bash
python tools/publish_modrinth.py --dry-run --since 1.3.0.2 1.3.0.3
```

Without `--since` the dry run still prints only the newest section; without `--dry-run` the flag is ignored.

### Modrinth page text

`docs/modrinth/description.md` is about 350 words instead of about 600: a one-line pitch, four steps under "How to use", "What this version does better", "Good to know" (target, client only, what players without the mod see, the download privacy note) and "Licence and credits". The release script only creates versions and does not send this text.

## Verification

- 71 JUnit tests pass, unchanged from 1.3.2.0.
- 18 Python tests pass: 13 at 1.3.2.0 plus 5 in the new `ChangelogSince` class of `tools/test_publish_modrinth.py` (every version not yet uploaded collected, next version after an upload, first upload, never reaching upstream history, published numbers without the `+26.3` suffix).
- The mod code is identical to 1.3.2.0, which the owner checked in game on 2026-11-18 and reported that everything works ([[v1.3.2.0 clovi.ru and page links]]).

## Release state

1.3.2.1 is the version released now, with the tag `v1.3.2.1` on 2026-11-18 ([[Release to Modrinth]]). It is the first Modrinth version with the link codes, the 1.3.1.1 fixes and the clovi and page-preview support. 1.3.1.0, 1.3.1.1 and 1.3.2.0 are never tagged. The result of the tag run is not recorded here.
